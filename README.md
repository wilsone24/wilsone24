## About

I build and operate the data platform that business teams run on: ingestion, transformation and
serving layers on **Databricks + Azure**, written in **Python/PySpark** and **SQL**.

I come from a software background, so I treat pipelines like software — version-controlled,
reviewed, tested and deployed, not clicked together in a UI. That same background is why I'm
comfortable on the other side of the pipeline too: designing **REST APIs and microservices**
that produce or consume the data, and packaging them with **Docker**.

- 🏗️ **Lakehouse engineering** — medallion architecture, Delta Lake, incremental/merge loads, Unity Catalog
- ⚙️ **Orchestration & CI/CD** — Databricks Jobs and Asset Bundles (DABs), Git-based deployments across dev/prod
- 🚀 **Performance** — Spark tuning: shuffle and skew, join strategy, partitioning, serverless migration
- 🔌 **Backend** — FastAPI / Node.js services, relational modeling, containerized delivery
- 🌱 **Learning now** — **Terraform** and infrastructure as code, to own the platform end to end
- 🤖 **AI-assisted engineering** — I use **Claude** daily, and build custom agent skills that encode our team's
  migration, review and deployment standards

## How I work

| Principle | In practice |
| :--- | :--- |
| **Pipelines are software** | Everything in Git, reviewed by PR, deployed through bundles — no notebook-only changes in production |
| **Idempotent by default** | Reruns are safe: merges and date-partition overwrites instead of blind appends |
| **Read less, shuffle less** | Push filters down, pick the join strategy on purpose, measure before and after |
| **Contracts at the edges** | Typed APIs and explicit schemas between services and the lakehouse |
| **Automate the repetitive** | Codified team standards as reusable agent skills and CLI tooling |
